# Compass 第 21 课 PRD · 系统提示词与 Context Runtime

Feature 975 · 产品评审稿 · 负责人 andy · 2026-11-19

## 1. 背景与目标

同一个“上周实付额”可以出现在晨会答复、渠道对比表、看板或财务周报里。经营人员需要一致的指标口径，也需要适合当前工作的交付形式。平台管理员需要在线调整提示词，发布后能在下一份匹配的业务结果中看到变化。

**Context Runtime 的目标**是让 Compass Agent 在任务的每一步都能用上当前用户有权使用、且足以完成这一步的信息。它结合租户、部门、任务类型和执行阶段，选用已发布的系统提示词片段、指标口径、已确认的对话条件、业务数据，以及适用的工具与 Skill。材料过多时，优先保留影响结论的数字、单位和适用范围。缺少关键条件时，向用户追问或说明结果的局限。

例如，用户先问“上周哪个渠道贡献的增量最大”，再说“把刚才的分析写成财务周报”。Context Runtime 应沿用已经核对的期间、渠道和指标口径，同时选用财务部的报告模板和报告交付要求。用户可以直接拿到摘要和完整周报，免去重新描述分析条件的步骤。

**PromptOps 的目标**是让平台管理员在现有 Web 管理模块中维护、发布和恢复提示词。管理员发布新版财务周报模板后，Context Runtime 在新受理的匹配任务中使用新版，已开始的周报沿用原版。授权维护者可以查明一次任务实际使用了哪些版本和材料。

## 3. 总体业务流程

### BF-01 · 提问到交付

1. 用户在分析 Chat 提问，或接着上一轮提出新的交付要求。
2. Compass 识别用户要拿到什么。交付形式或指标有歧义且会改变结果时，先澄清最关键的一项。
3. 结合所在租户、部门、场景和阶段，选用适用的提示词、材料、工具及 Skill。按问题选择适用的研究方法，说明影响结果的缺项。
4. 在原会话给出答复或产物入口。用户可继续追问、重开看板或下载报告，查看时按当前权限判断。

### BF-02 · 编辑到发布与回滚

1. 平台管理员首次导入集中维护的本地提示词，预览并整体发布，形成首个线上快照。
2. 日常在文件树中找到目标文件，查看使用位置，编辑 Markdown、试填模板变量并保存草稿。
3. 确认正文和影响范围后单独发布，或将准备好的草稿整体发布。管理员从目标工作空间发起新任务，核对实际答复。
4. 如需恢复，只改一个文件时从文件历史恢复并再发布。需要恢复全套配置时选择整库快照。操作记录保留发布人、时间与说明。

## 5. UI 视觉与交互

### UI-01 · PromptOps 管理

管理员从「管理与治理 → 平台管理 → PromptOps」进入，按目录或搜索定位文件，查看正文、变量、使用位置和历史。保存草稿与发布分别操作。确认页显示本次发布对象，冲突时保留输入，窄屏和键盘操作均可完成编辑与确认。[PromptOps 产品需求](PRD.md) · 交互原型

### UI-02 · 分析 Chat

问答直接读正文，分析表格可在窄屏内滚动。看板和报告显示生成进度，保存成功后显示具名入口。失败时保留原问题和可用结论，并提供重新生成操作。历史内容在重开或下载时核对访问权限。

## 6. 业务规则与约束

### 6.1 业务规则

- 有多种工作步骤时按用户最终要的交付物确定场景，例如带图表的周报仍按经营报告交付。
- 本轮明确指定的筛选优先于上轮条件。部门模板可调整表达和版式，指标采用所在工作空间确认的定义，权限按当前身份判断。
- 信息过多时优先保留问题、关键数字、单位、日期及口径。缺失会改变结论时先澄清。需要的工具未获授权时，同时停用依赖它的 Skill。
- 发布共享文件会影响所有引用它的新任务。新增文件在接入前显示“尚未接入”。管理员可以改正文和版本，租户与部门的调用关系由 Compass 预设。

### 6.2 量化门槛与口径

| 检查项           | 验收口径                                                                               |
| ---------------- | -------------------------------------------------------------------------------------- |
| 场景交付         | 四类全部达到扩展规格中的最终答复和产物要求                                             |
| 上下文组合       | 四类各 20 个固定样例，80 个中至少 79 个符合预期（≥98%）                                |
| 业务回归         | 四类各 5 个覆盖不同业务主题的固定问题，20 个中至少 19 个通过（≥95%），关键行为全部通过 |
| 上线连续性与隔离 | 发布或恢复后 60 秒内生效，已受理任务因变更发生的关键中断为 0，权限隔离用例 100% 通过   |

## 7. 范围与依赖

首版覆盖四类任务、文件级提示词管理、整体快照和任务运行观测。部门沿用当前租户下的工作空间。业务交付依赖该空间已确认的指标释义、可用业务数据、已授权工具和 Skill。管理员沿用现有平台账号权限。

## 2. 一棵对应本地的文件树

树根是本地集中管理的 `prompts/`，文件的完整相对路径是管理、版本和代码引用共同使用的标识。相同文件名可以出现在不同目录。每份系统提示词、场景模板、共用片段和辅助提示词都有自己的 Markdown 文件。首次上线的盘点覆盖主分析、识别与澄清、查询与工具说明、Skill 片段、子任务、标题、预填提问和最终输出。验收时以实际交付的完整本地清单核对。

| 目录                     | 管理员如何查找                                                               |
| ------------------------ | ---------------------------------------------------------------------------- |
| `tasks/business_qa/`     | 经营问答的 `system.md` 与 `scenes/metric_lookup/answer.md` 等场景文件。      |
| `tasks/data_analysis/`   | 数据分析的任务指令，以及 `scenes/period_comparison/` 下的周期对比模板。      |
| `tasks/dashboard/`       | 看板创建的任务指令，以及 `scenes/channel_overview/` 下的渠道概览布局提示词。 |
| `tasks/business_report/` | 经营报告的任务指令，以及 `scenes/weekly/` 下的通用周报和财务周报。           |
| `shared/`                | 跨任务复用的基础片段、阶段指令、工具说明及 Skill 指令。                      |
| `support/`               | 路由辅助、会话标题、子任务和产品预填提问等后台或入口提示词。                 |

**文件的位置与调用关系分别有明确的用途。** 目录帮助人找到文件。Compass 代码决定给哪一个租户、部门工作空间、任务、场景与阶段装载哪些路径、工具和 Skill。管理页以只读方式说明文件的使用位置。共享片段发布后影响所有引用方。新建文件可保存、发布、进入快照，待代码引用该路径后才参与实际任务。工具和数据权限沿用现有授权。

**首次上线。** 管理员导入随包提供的完整本地目录，核对路径后保存为线上草稿，再整体发布初始版本。线上数据库持久保存文件正文、草稿、发布历史和快照。应用重新部署后继续使用当时的生效版本。

**本地与在线协作。** 再次导入时按相对路径核对正文。相同内容可跳过，新增文件进入自己的目录。本地与在线都改过的文件展示差异，由管理员选择是否采用本地正文作为新草稿。导入保留线上生效版本与本次目录未包含的文件。线上新建的文件标为“线上新增”，可下载 Markdown 放回同一相对路径。原型所用的本地目录

## 3. 文件版本与整库快照

| 操作                       | 管理员确认的内容                                                                                       | 生效结果                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 保存文件草稿               | 当前路径、Markdown 正文，模板可试填期间、单位等变量。                                                  | 一份文件可有一份待发布草稿。保存后可刷新重开。                                                                                   |
| 发布此文件                 | 只查看该文件由哪个版本变为哪个版本、修改的正文、只读使用位置与发布说明。                               | 本文件生成自己的不可变版本号。其他文件和既有快照都保持原记录。                                                                   |
| 整体发布                   | 确认所有已保存草稿、各自将生成的版本、前次快照之后已单独发布的变化，并填写说明。未保存的编辑另行提示。 | 所有候选一次生效，生成一个含**全部生效文件路径与确切版本**的快照。未改文件沿用原版本号。任一候选无法发布时整批保留原状。         |
| 仅有单文件发布后的整体发布 | 确认此刻的完整生效清单。                                                                               | 可以为当前组合留下新快照，无需为已发布文件重复升版。清单与最新快照相同且没有变更时直接查看已有快照。                             |
| 查看或恢复快照             | 查看快照编号、说明、操作者、时间，点开任一条目读取当时的正文。恢复前确认涉及的文件与版本。             | 一次恢复整份生效清单，并留下新的恢复快照。后来新增的文件保留历史，退出生效清单。已有草稿保留，基线发生变化的草稿须核对后再发布。 |

每次任务受理时固定当时生效的文件版本组合。管理员可在整体发布后继续单独升级任何一个文件。此时最近的快照仍记录整体发布当天的组合，线上任务采用随后生效的新组合。查看旧报告或继续已受理任务时使用当时的内容。

## 4. 界面与反馈

- **文件库。** 左侧按原路径逐级展开，支持搜索路径、文件名或标题。选中文件后，右侧显示路径、使用位置、草稿与生效版本，可在 Markdown 预览、源码编辑和本文件的版本历史之间切换。预览渲染标题、列表、引用、表格及代码块。模板变量保留原名，可单独试填样例。
- **新建与编辑。** 在树中选定目录后点击“新建提示词”，填写目录、文件名和正文。新场景可随文件创建子目录。路径重名时定位到已有文件或修改名称。空正文、未支持的变量在发布时提示具体文件。两人改同一份正文时保留后提交者的输入，先比较线上最新内容再决定继续保存。
- **发布与回看。** “发布此文件”位于正文区。“整体发布”和“整库快照”属于库级操作。发布前可取消，成功后明确显示文件版本或快照编号。草稿、单文件生效与最近快照用文字区分。
- **权限与窄屏。** 平台管理员可管理文件、发布和恢复。租户管理员和普通成员通过受权的业务功能使用结果。窄屏可收起文件树以阅读或编辑正文，键盘可展开目录、选择文件、确认发布和取消弹窗。

静态原型内置完整的教学样例，直接打开即可使用，也可选择本地 `prompts/` 目录试导入。原型数据保存在当前浏览器，真实业务效果在 Compass 对话中验收。打开 PromptOps

# 四类经营场景的方法与交付要求

本规格是[主 PRD](PRD.md)的场景扩展。四类场景按用户希望拿到的结果划分。同一个业务主题可以先做问答，再展开分析，最后形成看板或报告。切换场景时，已确认的事实、指标口径和范围可以沿用，研究方法和表达方式随新的交付目标调整。

## 共用原则 · 如何找到适用的指标语义

用户说的通常是业务用语，工作空间里维护的是指标定义。**指标语义召回**要解决的是两者能否对上，以及找到的定义能否用于眼前这个问题。

1. **理解用户在衡量什么。** 从问题和已确认的对话中识别对象、关注的现象、范围与用途。用户可以先描述业务现象，Compass 负责找到可能相关的指标。只问业务规则且无须量化时，可直接使用适用的规则说明。
2. **把候选放回业务语境。** 从当前有权使用的指标释义中，结合业务名称、别称、相关概念和定义寻找候选。判断时看统计对象、适用范围、生效期间、时间粒度、聚合方式和单位。涉及比率或比较时，还要看分母或参照对象。名称相近只是查找线索。
3. **处理会改变答案的歧义。** 定义明确且适用时直接采用。多个定义会产生不同答案时，用业务语言说明差别，请用户选定。找不到适用定义时说明缺什么，已有部分能回答的先回答。用户明确指定的临时算法应标作本次约定，便于和工作空间的正式口径区分。
4. **随用途复核。** 同一问题的追问可沿用已确认的定义。对象、期间、汇总层级或工作空间变化时，重新判断定义是否适用。最终答复只展开影响理解或决策的口径细节。

下列上下文清单描述各类任务通常需要的材料。已确认的信息可以复用，按本次问题补齐必要材料即可。各场景的工作方法供选择和调整，具体提示词由 PromptOps 维护。

<a id="business-qa"></a>

## 经营问答 · 把眼前的问题答清楚

**研究方法。** 先辨认用户是在问事实、含义、规则，还是在核对自己的理解。确定什么信息足以回答这一问，再决定是否取数。遇到歧义时，比较不同解释对答案的影响，只追问会改变结果的条件。

**指标语义召回。** 优先找到与问法和对象最贴合的定义。问“是什么意思”时，解释它衡量什么、适用在哪里。问“是多少”时，再核对读数的期间、范围和单位。数值为零、没有记录、数据尚未齐备，分别说明。

**默认上下文。** 当前问题和必要的上一轮指代、所在工作空间适用的指标释义或业务规则。需要查数时再带入已授权读数、范围和数据截至时间。

**回答风格与产物。** 简短、直接，先给用户要的答案，再解释影响理解的条件。交付物是原对话中可以重读的答复。读者应能分清“答案是什么”和“它在什么条件下成立”。

<a id="data-analysis"></a>

## 数据分析 · 让结论经得起比较

**研究方法。** 把用户的疑问转成可以用数据区分的判断，再选比较、分解、趋势、分布或假设检验等适用方法。先观察整体，再沿有解释力的维度查看差异。判断一个解释是否成立时，考虑样本构成、口径变化和其他可能原因。材料只支持描述变化时，结论就停在变化本身。

**指标语义召回。** 从研究问题出发，先找能衡量目标现象的指标，再根据待验证的解释补充相关指标和维度。重点核对比较双方是否覆盖相同的对象、期间和统计粒度。对比例或派生指标，确认分母及聚合条件。口径变化时，优先使用可比范围，并说明这一选择如何影响结论。

**默认上下文。** 待回答的问题、分析对象、主指标释义、可用维度和数据覆盖情况。比较任务补入参照对象，解释性任务按需补入业务事件、替代解释和可用于核查的观察。

**回答风格与产物。** 结论先行，随后给出最能支撑判断的比较，并区分观察、解释与待核实事项。交付物是可复核的分析结果。按问题选择对比表、图或文字，保留读懂结果所需的范围、基准与单位。用户要求导出数据时，CSV 应与答复采用同一范围和口径。

<a id="dashboard"></a>

## 看板创建 · 让读者能自己观察和比较

**研究方法。** 先明确看板供谁使用、打开后要判断什么，再决定呈现哪些指标、如何分组、需要哪些比较与筛选。选择视图时考虑读者是要看水平、变化、结构还是差异。用读者最关心的问题检查布局，确认他能从总览找到需要进一步查看的部分。

**指标语义召回。** 从观察目标选出主指标及有助于解释它的维度。检查各视图采用的时间粒度和筛选范围，特别关注汇总到明细、改变分组后指标是否仍有相同含义。比率等指标应按其定义汇总。不同视图有意采用不同范围时，在对应位置标清差别。

**默认上下文。** 目标读者、观察目的、已确认的指标与维度、筛选条件、数据覆盖与截至时间，以及本次希望沿用的已有视图或分析结果。

**回答风格与产物。** 对话中简要说明看板能回答什么、从哪里开始看，并提供打开入口。主要交付物是可从原会话重开的看板。看板本身应标清主题、范围、单位、数据截至时间和缺数状态。读者重开后能看到创建时的读数和筛选。

<a id="business-report"></a>

## 经营报告 · 围绕读者要作的判断组织全文

**研究方法。** 明确读者、用途和核心议题，围绕这些议题选择值得写入的发现。将相关观察串成有主次的论述，说明变化意味着什么、哪些解释仍待核实。报告需要支持决策时，建议应能对应到具体发现，并交代适用条件。篇幅和章节随读者需求及已生效模板调整。

**指标语义召回。** 按报告要表达的关键判断选指标。核对同一指标在摘要、正文、图表和引用材料中的定义与期间。引用目标、预测或历史值作参照时，标明其性质，并核对与实绩的可比条件。来源口径存在差异时，说明采用哪项定义以及对解读的影响。

**默认上下文。** 报告用途、读者、覆盖范围、适用的部门模板、已核对的指标释义和分析发现。按议题补入比较基准、业务背景、重要限制或上次待跟进事项。

**回答风格与产物。** 对话摘要突出读者最需要知道的判断。完整报告应有清晰主线，重要结论有相应事实支撑，脱离聊天记录也能独立阅读。提供打开和下载入口，首版支持 Markdown 下载。摘要、正文与下载稿中的判断、数字和口径应一致。
