## 1. 背景与目标

管理层、财务、市场与门店用同一个「销售额」提问时，可能分别需要成交 GMV、净销售额、营销归因成交额或授权门店成交额。指标的时间字段、去退款规则、聚合粒度和组织范围会改变结果。Compass 要让团队能盘点、定义、审查并发布这些口径，让 Agent 按当前用户权限和发布版本执行查询，并将口径显示在分析结果中。

首期至少发布销售、营销、库存三个业务域。财务定义用于验证同名冲突，财务域可随素材成熟扩展。量化目标及计算方法统一见 AC-10，目标值待实施后实测。

**需求顺序。** 先按企业语义内容专项需求盘点术语与别名、指标定义、实体与关系、可信执行资产。由业务专家和数据负责人共同核对字段、业务时间、依赖、作用域及数据来源。只有能说明来源并通过验证的定义，才能用作正式指标。内容清单和示例口径在专项文档维护，管理、运行与交互的验收统一在本文维护。

**当前产品起点。** Compass 已有「数据与语义 → 指标口径」导航占位、受管只读查询、可恢复的 Chat 与人工确认、Context Runtime 和 PromptOps。现有文件型口径字典可按租户、工作区、来源和有效期匹配指标。第 22 课需要把正式定义、版本与审批落入 PostgreSQL，并把按权发现、前端选口径与保存指标草稿接入上述入口。

## 2. 用户与场景

| 用户         | 场景                         | 所需能力                                               |
| ------------ | ---------------------------- | ------------------------------------------------------ |
| 语义维护者   | 指标盘点、接入报表或修订公式 | 登记来源，发现候选、比较差异、提交审批                 |
| 业务专家     | 指标进入评审                 | 确认适用对象、业务含义与异常规则                       |
| 数据负责人   | 业务通过后                   | 验证可执行性、权限及影响，批准发布候选                 |
| 发布负责人   | 已批准版本拟生效             | 选择全量或灰度对象，跟踪发布、回滚及历史               |
| 授权经营用户 | 从分析 Chat 提问             | 查询、对比、下钻，选择或补充口径，勾选值得保存的新指标 |
| 评测负责人   | 版本发出前及上线后           | 用固定样本复测定义修订                                 |

有草稿创建权限的用户可以建立个人指标，默认本人维护、发布后仅本人使用。组织指标由对应管理员或获委派的维护者管理。使用指标准入与计算所需的数据访问权分别校验。各身份的权限见 §6.1。

## 3. 业务流程

1. 维护者按业务域盘点已有口径，录入 Schema、历史 SQL、BI 指标清单、报表及业务文档。AI 生成候选和审查建议，维护者编辑后提交。
2. 业务专家确认含义，数据负责人验证计算与授权。退回时显示原因，修订后重新评审。已批准候选展示受影响对象，发布负责人选定灰度范围或全量发布，可回切仍有效的历史版本。
3. 经营用户问「上月销售额是多少」。Agent 从当前可用的术语和指标摘要开始，依问题检索并核对口径。问题或前文明确指向成功支付时，结果标注「支付 GMV」、期间、范围和版本。若用户同时有权查询成交额与净额两种口径，且上下文无法区分，Chat 暂停该项执行，请用户在原轮次选择。选择成功后继续此前的对比或报告任务。
4. 评测覆盖同问不同角色、多指标、多维度及跨域报告。维护者修订相关定义后，用原样本回归。
5. 缺少正式口径时，用户可在授权的连接上做开放查询。Agent 可根据本轮已核实的计算，向用户建议目录尚未覆盖且有持续决策价值的指标。用户也可在同一会话下一轮提出「把刚才按渠道算的净额存成指标」。主动建议支持批量勾选并保存到个人草稿。用户直接提出保存时可核对和编辑定义、选择有权维护的归属范围。

| FR-09 | 评估及持续优化       | 针对固定样本计算五项效果指标，记录失败类别和版本。维护者可修订定义并用同一样本复测。                                                                                                                     |

## 5. 界面与交互

打开高保真交互原型。左侧可在指标口径管理、Chat 创建草稿、修改口径、选择销售额口径四个场景间切换。确认后写入的演示草稿可在管理页查看，审批、发布和真实取数沿用本文的实施要求。

### 5.1 「数据与语义 → 指标口径」

拟将现有占位页接为指标维护入口。列表、详情、编辑与 Chat 共用同一份定义和权限判定。没有管理权限的经营用户可通过 Chat 查看对其公开的定义。页面沿用 Compass 的界面样式与状态约定。

```text
指标口径
[业务域] [归属范围] [发布状态] [搜索]          [新建指标] [登记来源] [生成候选]
指标列表                              详情    定义 / 依据 / 依赖 / 版本
订单数      全局预置    已发布          名称、适用范围、负责人、生效版本、可用连接状态
销售额      销售部共享  草稿            [编辑草稿] [校验口径] [提交评审]
```

- **填定义。** 新建时分别设置「维护归属」和「发布后谁可用」，默认值分别为「我」和「仅我」。只有具备相应授权时才能改选组织归属或分享给更大范围。录入名称、别名、适用场景、负责人、公式、归集时间与粒度、单位、过滤条件、允许下钻的维度和执行绑定。选取实体与字段时只返回已授权来源。未补齐来源、粒度或校验的条目可存草稿，不能送审发布。
- **看差异。** 输入同名或已有别名时列出可见候选的定义与范围。用户可打开现有指标，或说明业务差异后创建独立口径。部门要调整公共口径时，可从可见定义派生独立指标，保留来源版本。公共原件由其归属范围维护。
- **修订已有指标。** 维护者打开已发布资产时，页面显示「创建修订」。已有可编辑修订时显示「继续编辑草稿」。原发布版照常服务，修订通过审批并发布后生效。仅有使用权的用户看已发布定义，无草稿入口；若具备创建权，可以派生独立指标。
- **审阅与恢复。** 校验在出错字段旁显示原因。提交、发布和回滚前展示目标版本和受影响人群。请求期间阻止重复提交，失败保留输入。过期版本要求刷新核对。空列表引导首次创建或搜索。窄屏表单单列、候选卡换行。键盘可选择选项并确认，弹层关闭后焦点回到触发控件。

### 5.2 Chat 选择口径

选择卡最多提供三个当前可见的候选，展示各自的业务含义、归期、版本和单位。用户也可自行补充算法。正式取数时校验所选绑定和执行权限。

```text
找到多个「销售额」口径，请选择本次查询的口径。
○ 支付 GMV  · 销售部  · 按支付日统计已支付金额
○ 确认收入  · 财务部  · 按确认日统计已确认收入
[都不合适，我来补充算法]
[取消本次查询]  [选择并继续]
```

用户须主动选定一项。「选择并继续」回传本次候选标识。当前 Run 停在原问题。刷新或重连可看到同一待选项。已处理的卡片显示选择及结果。重复点击仅消费一次。若权限、版本或候选有效性变化，刷新可选项。无可见候选且口径不清时，向用户询问算法。独立的授权明细查询继续执行。用户选择保存在本次 Run。多指标比较已明确指定两个指标时，分别解析执行。

### 5.3 Chat 保存指标草稿

1. **主动邀请。** 普通查询交付答案。模型确认新指标具有可重复使用的经营决策价值，核对现有定义并关联本轮成功回执后，才生成保存建议。每轮最多三个候选，同一张多选卡展示各项业务名称、统计口径、公式和复用场景。「保存所选」将勾选项写入个人草稿。「暂不保存」收起本轮剩余建议。
2. **用户要求。** 后续轮次明确提出保存时，允许直接进入预览，无需先收到邀请。按同一会话的已完成查询回执定位用户所指的计算。「刚才那个」可能对应多项时先列出可见的结果名称和时间请用户选定。遇到过期、无权或无法还原的来源，提示重查或补齐字段。
3. **明确要求保存时的预览。** 从原始问题、被选中的查询回执及执行计划提取建议名称、业务含义、可复用公式、业务时间、统计粒度、单位、维度和来源。把「上个月」「华东」等本次输入单列为参数样例。若它们确实属于固定业务定义，由用户在预览中确认。展示缺失信息和潜在重复项，允许修改名称、定义和负责人；新建时显示维护归属，分享选项列出当前操作者获准的发布使用范围。修订已有指标时保留原归属。模型生成的 SQL 和数据行均不能直接成为正式执行绑定。
4. **确认写入。** 用户在建议卡上点击「保存所选」，或在可编辑预览中确认后，才创建指标草稿。取消、关闭、失败或缺少写权限时可继续查看原结果。网络重试和重连应返回同一草稿。草稿回执链接到指标口径页，后续校验、提交、双人审批和发布沿用管理流程。保存时如发现同范围等价定义，提示查看现有指标。用户在 Chat 明确提出修订时，先校验当前资产的维护权，再预览与现版的差异。已有可编辑草稿时继续该修订，确认后保存。只有使用权的用户可以查看已发布版或在有创建权时另建独立草稿。

| 触发                               | 拟议文案                                                             |
| ---------------------------------- | -------------------------------------------------------------------- |
| 当前无正式口径且用户有开放查询权限 | 当前没有可用的正式口径。可以调整问题，或使用授权数据做一次临时查询。 |
| 缺少执行权限或数据绑定             | 该指标暂时无法正式取数。已明确的算法可在获准明细上计算，同时交付其他已完成的查询。               |
| 当前版本变化导致发布冲突           | 发布状态已更新。请刷新并重新确认发布范围。                           |
| 影响范围不完整                     | 已列出系统内登记的依赖。请补充核对外部报表与查询。                   |
| 澄清期间候选失效                   | 可选口径已更新，请重新选择。                                         |
| 跨轮引用不清                       | 你想保存哪一次计算？请选择要提取的结果。                             |
| 草稿写入成功                       | 「{指标名}」已保存为草稿。[查看草稿]                                 |

## 6. 业务规则

- **BR-01 作用域。** 同名可关联不同稳定指标 ID。可执行范围由租户、工作区、授权数据和发布规则共同决定。查询里的部门或岗位仅用于表达意图，服务端从授权身份获取实际范围。同名候选在相同优先级冲突时澄清。可展现的候选也必须通过访问检查。
- **BR-02 计算口径。** 采用定义绑定的业务时间与统计粒度，计算区间使用左闭右开。库存快照只能按对应时点策略汇总。比率从同一范围内的分子分母重新计算，分母为零标为不可计算。跨域先对齐时间、单位、维度和粒度。无数据与数值零分别呈现。
- **BR-03 审批与发布。** 作者、业务确认人和数据审批人按职责分离，两次审批须来自不同人员。审批绑定候选内容版本。发布与回滚留存操作者、理由、影响范围和前后版本。灰度面向明确的授权工作区或组织人群，其他人沿用原发布版本。
- **BR-04 版本一致性。** 单次运行固定生效发布。恢复、重试及每次工具查询复核当前权限。权限撤销、发布撤回或来源停用后，拒绝后续计算及失效结果交付。回滚按历史定义生成新的发布事件。
- **BR-05 数据保护。** AI 只处理获授权来源，不向模型传入连接凭据或完整敏感样本。权限不足、定义非法或不可安全执行时不发起查询。审计、评测及报告按各自访问权限展示。

### 6.1 谁可以看、用和维护指标

每个指标分别记录**维护归属**和**发布后的使用范围**。前者决定谁能改定义、建修订、改共享设置和提交；后者决定谁能发现、阅读已发布版本，以及在数据权限允许时查询。同一归属可以对应不同使用范围，例如个人指标分享给销售部后仍由本人维护。

| 维护归属 | 谁能维护                                                             | 发布后的使用范围                                                                           |
| -------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 个人     | 属于当前租户的本人。具备建草稿权限的用户可从管理页或 Chat 为自己创建 | 默认仅本人。本人有相应分享权限时可选择所在租户内获准的部门或租户范围。接收者只读           |

默认发现时先裁剪可见候选，再识别适用业务含义。Agent 根据问题中的业务事件、前文和已确认的选择核对定义。仍有多个合理解释时进入 FR-12。无权资产的名称、数量、别名、示例及执行结果均不出现在提示、搜索、澄清或历史回放中。全局共享定义可以描述公式，租户私有连接、字段映射和样例数据另按授权展示。

### 6.2 DataAgent 如何取得答案

对经营分析任务，首个模型步骤提供当前有权访问的核心术语、指标名/ID、口径短释和版本。受上下文预算限制时仅保留与任务相关的摘要，并提供动态检索入口。模型按问题决定使用 `search_semantics` 搜索术语、别名、指标或实体，使用 `get_metric_definition` 核对业务时间、粒度与排除项，使用 `resolve_semantics` 取得可执行方案或澄清。搜索优先精确别名，然后匹配规范化关键词及受支持的文本检索。默认摘要中未出现的指标仍可主动发现。取得正式指标数值时用 `query_metric` 读取发布绑定。口径已经明确且正式绑定缺失时，可在当前使用者获准的明细上按定义计算，注明实际来源和算法。模型不得根据名称、示例值或相似口径代答。唯一合法且参数齐全时可结束检索。没有新线索、预算耗尽或有关键歧义时分别返回未匹配、请补充或请求选择。系统提示词固定这些运行原则，技能可补充域词汇及澄清示例。授权、发布与执行参数由服务端强制校验。

经营用户有三条可区分的取数路径。正式指标通过 Metric Query 解析定义并绑定发布版本。已登记的可信 SQL 仅接受获准参数，可作为正式指标的执行资产并返回版本回执。开放分析通过现有 `database_query` 做授权只读查询，标注临时口径。模型将工具返回的缺少绑定、权限不足、无匹配、参数缺失和执行失败作为后续决策的输入，继续完成可独立回答的问题。用户可从可见候选中选择，或填写自己的计算方法；未找到定义时可直接补充算法。数据访问仍遵循当前主体的连接、字段和行范围，撤权后重新校验。

管理时，`discover_semantic_candidates` 从授权素材或已选查询回执提取候选，`review_semantic_change` 返回校验及修订建议，`submit_semantic_change` 在用户要求送审且具备相应权限时提交指定草稿。保存确认只创建草稿。批准、发布和回滚由相应责任人执行。具体工具入参、返回状态与身份来源见[技术方案](TECH_DESIGN.md)。

## 7. 交付范围与依赖

首期用 Compass 现有受管连接与零售合成数据，对 BI、历史报表和文档以授权快照或输入材料完成盘点。首期通过分析 Chat 交付报告，查询及报表影响分析覆盖有登记引用的资产。完整外部平台自动同步和通用跨数据源联邦计算列为后续能力。

教学验收覆盖两家合成租户、销售/财务/营销部门和销售/营销/库存至少三个核心业务域。指标样例包括支付 GMV、净 GMV、订单数、确认收入、广告投放口径及期末可用库存。对「广告 ROI」要先说明分子及成本规则，区分广告支出回报率（ROAS）与利润 ROI。数据不足时保留为待验证候选。实际物理映射、库存时点、财务时间和已具备的数据条件见[专项需求](PRD.md)。

启用数据库语义层的工作区从生效发布读取正式口径，原文件型字典的有效定义可经导入、校验和审批后启用。切换后新任务按新发布取数。切换前的运行按原绑定标识恢复，并重新校验当前授权。授权失败或历史定义不可恢复时说明原因。旧报告的口径来源及临时查询标识保留。

## 1. 本课要交付什么

用户问「上月销售额多少」，Compass 应能说明采用了谁发布的口径、按哪个经营事件归期、算入了什么，以及当前身份能查到哪一部分。为此先建立企业经营词汇表、指标字典、实体关系目录和可信执行绑定清单，再将可用内容提供给指标管理页与分析 Chat。

### 历史时点、报表版本与完整度

每次查询区分所问的**业务期间**与用户在何时可以看到这些数的**数据截至时点 K**。时间戳比较使用同一时区的绝对时刻，已到达的边界包含在内（`available_at <= K`）。数据集发布号、K 和实际采用的报表版本随结果返回。下单数、支付额、净 GMV 和确认收入分别按上表的事件时钟过滤。支付和退款只取 `SUCCEEDED`，按销售维度分析时再沿原订单取值；退款日计算本期现金流净额时，保留原单在上期的退款。完整数据集上没有事实取 0，授权缺失、来源迟到或完整度未知应保留相应状态。

**净 ROAS 的取数顺序。** 教学绑定覆盖有平台归因 feed 的活动。先用租户、平台渠道、活动生效区间与所问日期确定应有的活动日，活动外的日期不计入分子或分母。日期对齐使用 `campaign_attribution_daily.cohort_date = campaign_daily.report_date`。对每个应有活动日执行以下步骤。

1. 选择当前租户、活动、渠道中归因规则为 `PLATFORM_LAST_CLICK_7D`、`model_version='1'` 且在 K 前已可见的归因日行（含 K），取最高 `report_version`。此教学源 v1 观察日在归因日后第 8 天，v2 在第 61 天，实际可见还受入库延迟影响。新版本保留已冻结的归因支付金额并更新累计退款。使用所选行自身的 `coverage_status`，未知时返回未知，禁止回退到较早的已知金额。
2. 消耗按租户、活动、渠道、报表日、地区分别在 K 内取最高可见 `report_version`，再汇总到活动日。教学活动每天投放在计划地区 1–7，数据包的消耗版本为 1，必须查齐七个地区。正式接入按绑定登记的投放计划和对账规则判断应到地区；缺失和已到零消耗分别返回。教学源的 `asset_period_status` 记录商品渠道日报的完整度，广告消耗须独立核对。
3. 所选范围内每个应有活动日均有已知归因与完整消耗，才按总归因净额除以总消耗生成总计；分母为零单列「零消耗」，全窗口无适用活动则显示「无适用活动」。若混有归因缺报、未知或消耗不完整，允许列出已知明细及缺口，总计显示不可计算。明确筛选地区、仅有地区级授权或请求按地区下钻时，拒绝此平台级指标。

**可复核的净 ROAS 样例。** 在诊断数据包的租户 101、活动 30、渠道 3，2025 年 6 月 1 日的七区消耗合计 8,053 分。K 为北京时间 6 月 10 日 00:00 时，归因 v1 已可见，支付 22,795 分、退款 0 分，显示 2.8306 倍。K 为 8 月 2 日 00:00 时，归因 v2 可见，累计退款 6,800 分，显示 1.9862 倍。两个结果使用相同的归因日与消耗，金额不做中间舍入。

**期末库存的取数顺序。** 对本地日期区间 `[D0, D1)`，取 `D1` 前一自然日为期末日 D。教学源在上海时间 23:59:59 生成当天期末快照，诊断包从 2025 年 10 月 1 日开始。以该租户生效的 `assortment.valid_from <= D < valid_to`、授权地点和商品筛出应有地点×SKU 组合并去重。逐组合核对 `snapshot_date=D`、`as_of` 为当日期末且 `available_at <= K`，齐备后汇总 `available_qty`。缺少组合时不回填前日、不拿日中采样补齐，返回缺口并留空完整期末合计。期末尚未到达时返回「未到期末」，早于首个快照日则返回「超出快照覆盖期」。零售包中 101 租户、地点 1、SKU 9 在 2025 年 10 月 1 日的期末可用量为 9 件，`as_of` 为 23:59:59，次日 00:00 才可见；K 相差一秒，结果可分别为「快照尚未到达」和 9 件。

**金额和时间示例。** 一笔含三个单件（80、10、10 元）的 100 元订单在 10 月 31 日成功支付，11 月 1 日妥投确认收入 100 元，11 月 3 日受理部分退货冲减收入 20 元，11 月 4 日成功退款 20 元，假定各期数据齐备。10 月支付 GMV 为 100 元，11 月现金流净 GMV 为 −20 元，11 月确认收入为 80 元。「上月」同时记录用户时区、解析时点和解析后的具体日期；历史重跑保留该窗口和数据截至时点。

**缺数处理。** 成功完成并确认覆盖完整的交易期间可以出现零笔或零金额；迟到、缺报及访问受限分别返回数据状态。退款与订单/支付、报表与活动、成本与权限都核准后才能计算对应口径。库存量映射到基准件，估值还需要金额权限与独立绑定。

## 5. 实体、维度和可用关系

下表给出首发计算能使用的主要路径。除日期日历外，所列零售主数据与事实键均带 `tenant_id`。物理关系含额外一致性键时按受审映射校验。数据负责人需给每条可用于计算的路径指定允许的粒度、裁剪规则和历史时点。

| 出发实体 → 目标              | 关系与键                                                                                                 | 可用条件                                                                                            |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 支付 / 退款 → 订单           | 多对一，分别由 `order_id` 关联订单头；退款有 `payment_id` 指向原支付                                     | 支付与退款分别汇总，禁止把一笔支付按其多笔退款重复计入。对多行订单按 SKU 切分金额需先发布分摊规则。 |
| 收入分录 → 单件 → 订单或 SKU | 多对一，依次使用 `order_unit_id`、`order_id` 或 `sku_id`                                                 | 支持单件口径的收入分析。订单数经明细下钻时按订单去重。                                              |
| SKU → SPU → 品类 / 品牌      | 多对一，使用 `spu_id` 后取 `category_id` 或 `brand_id`；品类有上级键                                     | 商品多运动标签经 `spu_sport` 映射，多标签汇总可能重复；标签分摊未定义时禁用该汇总。                 |
| 原销售地点 / 库存地点 → 网点 | 订单使用可空 `selling_site_id`，快照使用 `site_id`；网点再关联 `org_unit_id`、`geo_id`                   | 门店和仓按 `site_type` 区分。缺销售门店保留未归属，禁止把仓或退货接收地替代销售门店。               |
| 报表 → 活动 / 渠道           | `campaign_id`、`channel_id`。消耗报表有地区，归因报表没有；报告日期分别为 `report_date` 与 `cohort_date` | 先按各自自然键及报表版本挑选可见行，再把消耗聚合到共同粒度；覆盖检查贯穿所选日期。                  |
| 库存快照 → 地点 / SKU        | 每租户、日期、地点、SKU、`as_of` 唯一；地点、商品均多对一                                                | 选定同一期末再汇总。数据可见时点 `available_at` 与快照业务时点 `as_of` 同时参与筛选。               |

对实体和维度的词条也提供简单反例，例如「门店销售额」与「从该门店发货的金额」。跨域比较先确定共同粒度、窗口、金额单位和可见范围，再使用两个独立受控结果；无法对齐时展示各自口径和停止合并的原因。

定义可见、绑定可用、可读取业务数据三项分别标注。公共摘要不含租户私有别名、表定位、连接标识或查询结果。显式指定正式名称优先尊重用户意图；竞争的同名口径若结合当前问题和前文仍无法区分，Chat 展示可见选项的名称、范围、计算差异与时间字段，等待选择。同名资产不得自动合并，跨租户也不得互相覆盖。

Run 初始上下文只带已发布且可见的少量术语/指标摘要（名称、键、版本、范围标签、一句定义），优先收录与当前提问相关的可见定义。模型可主动检索别名、按业务域缩小候选、读取完整指标定义再查询。选择反馈属于当次任务；有维护权的用户可在工作台修订别名和公共定义。

一次未命中目录、经授权完成并得到用户认可的开放查询，仅产生可抽取素材。平台的「定义指标」、Chat 主动建议保存、用户后续明确要求保存，都应能组成同一种候选定义。候选卡显示问题与来源运行、拟定名称、含义、公式、粒度、时间、单位、维护归属、发布使用范围、拟绑定及缺口；可在预览时修订或放弃。用户确认保存草稿后，正式绑定由数据负责人核验，发布后才进入正式目录。原始一次性日期或门店值应由维护者确认是参数或固定业务条件。公开共享还需检查来源和共享权限，未经授权的用户只可在允许的范围内提出建议。

## 7. 业务验收样例

以下样例是主 PRD 功能验收的内容夹具。实施时冻结两个租户的受限身份、底表快照与可见截止时间，数值样例独立于模型给出的答案。

| 案例                 | 输入与预期结果                                                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目录与来源           | 用六个业务键逐一定位到所有者、适用范围、正式名称、单位、时间、关系和执行绑定。销售、营销、库存各有至少一个完成审批并可查询的样例。标明需要成本权限或源侧缺字段的资产不可误设为可执行。              |
| 公共阅读、分租户计算 | 101 和 102 都能读公共订单数定义，各自仅查询本租户订单；移除 102 的本地绑定后，定义仍可阅读，查询给出未配置反馈。101 的财务指标对 102 的搜索、补全和默认上下文均不可见。                             |
| 术语消歧             | 同一账号分别问成功支付、财务确认和扣退款的销售额，按当前权限匹配对应指标。仅问销售额且前文不明确时展示可见选项，确认后返回所选版本。                                                                |
| 基数与历史时点       | 使用第 4 节跨月样例。增加一条失败支付、再将退款拆为两笔合计 20 元，支付额保持 100 元。调早可见截止时间后，尚不可见的退款不计入并显示对应数据状态。                                                  |
| 平台归因与库存       | 分子为 90 元、消耗 30 元时净 ROAS 为 3 倍；消耗为零或归因覆盖未知时返回不同原因。地区专员无法执行全租户归因。相邻两天可用库存分别为 8 件和 5 件时，完整快照下的期末库存为 5 件。                    |
| 新口径沉淀           | 对尚未登记的指标完成开放查询并由用户确认；同轮建议和次轮「把刚才的口径存下来」均回指正确结果。抽取草稿能区分临时日期、固定规则与共享范围，拒绝/取消保留原分析，确认后经双角色审批才能对其他人发布。 |

上线前由对应责任人确认真实租户与岗位映射、术语指向、支付成功的生产时间字段、归因模型、结账/快照完整度及各租户授权绑定。教学样例的选择不自动写入业务租户配置。
