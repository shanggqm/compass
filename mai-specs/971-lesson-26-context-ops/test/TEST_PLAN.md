## 范围与依据

验证普通经营分析从真实 Web 登录、提交 Run、Agent 执行与上下文编译，到 PostgreSQL 投影、ContextOps 查询、快照审计及 Badcase 回放的完整业务链路。覆盖 AC-971-01 至 AC-971-08，以及 BR-07 的本人可见范围、设计评审补齐的撤权、审计失败与 TTL 行为。

PII 按修订后的 FR-05 分两道验收：模型输入中的密钥始终脱敏，用户主动提供的合法查询主键可保留；存储快照、审计、OTel 与 MCP 出口进行不可逆脱敏。派生权限按全部受限源并集（逻辑 AND）验收。

测试替身限于外部模型上游和需要可控故障的依赖。主业务用例使用真实 Web、Agent、数据库与授权入口；浏览器网络替换单独记录为 UI 失败恢复验证。统计真值来自测试数据和数据库记录，预期计数独立计算。

## 执行环境与数据

- 使用独立命名的 Web / Agent 测试库与专属零售夹具，数据库初始化通过现有迁移和教学身份入口。禁止重置日常数据库、旧库或现有数据卷。
- 复用 [Playwright 配置](../../../apps/web/playwright.config.ts)，Web 默认测试端口为 8110；Agent、模型上游及 Redis 端口由实施与验收双方协调后写入执行记录。当前 8101–8103 日常服务保持隔离。
- 登录角色至少包含同工作区的管理员、成员甲、成员乙，以及另一租户成员。内部授权用途为 `contextops_admin` / `contextops_read`，分别复用平台管理员身份和现有分析权限；所有权限经真实 Web 会话和 Agent 可信上下文核验，旧 `runtime_usage` 语义保持。
- 运行样本包含：正常成功、至少两轮会话、搜索空结果、工具错误、预算截断或压缩、安全拦截、含图表产物、旧版无投影 Run、没有记录的筛选条件。状态与产物分类使用实际执行结果。
- 安全输入使用合成哨兵：高确定性 API Key、邮箱、手机号、合法校验位身份证、与手机号长度相同的明确订单 ID、正文内闭合边界标记；不使用真实个人数据或真实凭据。
- 原始输出、浏览器截图与日志放入 `work/971-contextops/`。报告只登记必要摘要，不保存秘密值。
- 用户追加 Docker 实测后，建立独立 Compose 项目与数据卷，使用真实已配置的 Flash Provider 完成普通 Chat；原版 Langfuse 同时核验公开 API、界面和 ContextOps 跳转。模型凭据仅加密复制到专属测试库，原有配置只读保留。

## 业务验收用例

### TC-971-01：普通 Chat 到上下文洞察的完整链路

- 关联需求：AC-971-01、AC-971-02，FR-C01。
- 前提与数据：已发布提示词、已授权零售连接；确定性故障场景使用受控模型，Docker 普通 Chat 使用实际模型 Provider，完成语义/检索、工具查询和回答，记录提交前的投影数量。
- 操作步骤：登录后通过分析页发送普通经营问题，等待 Run 完成；点击回答卡的“上下文洞察”；刷新后重新打开同一 Run。
- 预期结果：Run 真实执行完成；出现关联该 Run 与逻辑调用的新投影及加密快照；完整轨迹含实际发生的意图、搜索、编译、模型和工具节点；历史重读结果一致。旧版 Run 展示基础步骤并明确缺少上下文决策明细。
- 验证方式与证据：Playwright、BFF 响应与只读 PG 核对；保存 Run ID、版本、快照引用和桌面截图。

### TC-971-02：双轨迹视角与节点详情联动

- 关联需求：AC-971-02，FR-03、UI-01。
- 前提与数据：TC-971-01 的完整 Run，另有不同执行步骤的 Run。
- 操作步骤：切换“通用三轨瀑布”与“业务阶段分段”；依次切换时长/轮次/Token 尺度、搜索节点、点击阶段头和轨迹节点；切换 Run。
- 预期结果：两种视角共享同一轨迹数据；业务视角保留输入/模型/工具轨道并显示阶段分隔和统计；阶段选择联动明细与漏斗；四标签详情可打开且关联正确节点；漏斗、窗口构成与逐条决策同 PG 记录相符。
- 验证方式与证据：浏览器交互、BFF/PG 数值比对；桌面和 390 px 截图。

### TC-971-03：统计、意图与异常下钻

- 关联需求：AC-971-03，FR-04。
- 前提与数据：测试数据覆盖成功、压缩、工具失败、检索 `empty` 与安全拦截，至少两会话、不同轮数和不同场景。
- 操作步骤：依次筛选时间窗、场景、Policy 和管理员成员；切换意图及异常 Tab；点击异常项与意图明细进入 Run；选择无记录条件。
- 预期结果：顶部四组卡片持续可见；会话/Run 数、平均及极值轮数、完成情况、搜索轮数、终态/产物统计与独立计数相符；意图分布与 JEV/Flash/兜底来源、P50/P95 和异常热点使用真实值；空状态指标显示 `—`；筛选及下钻保持作用域。
- 验证方式与证据：读取实际运行记录独立计算计数和分位值，并核对页面/API；保存空态与异常下钻截图。

### TC-971-04：成员、会话与 Run 的可见范围

- 关联需求：AC-971-02、AC-971-03、AC-971-05，BR-07。
- 前提与数据：成员甲、乙在同工作区各有 Run，另一租户也有 Run。
- 操作步骤：分别登录管理员、成员甲和另一租户成员；访问列表、统计、Run 流、快照；成员甲篡改 `actor_id` 为乙或跨租户 actor；直接访问不可见 Run / 快照引用。
- 预期结果：管理员可按成员→会话→Run 级联；普通成员只见本人记录和统计，隐藏成员、全局安全审计与回放入口；服务端强制限定 actor 与租户/工作区；越权响应不返回目标摘要、正文或元信息。
- 验证方式与证据：独立浏览器会话和真实 HTTP 响应；核对普通成员默认与篡改筛选的结果集合。

### TC-971-05：在线四类安全防护与正常纠偏

- 关联需求：AC-971-04，FR-05、FR-06 与设计评审 P0-1/P0-2/P1-2。
- 前提与数据：四类攻防输入，以及“忽略之前口径重算”、订单 ID、合法用户查询主键等正常输入。
- 操作步骤：经真实 Context Runtime 编译租户错配、高危注入、中危混合正文、密钥/PII 和多源受限候选；至少一条工具返回从真实 Run 进入安全审计。检查模型所收请求、快照和审计。
- 预期结果：租户错配同步拒绝；高危条目阻断，中危可疑句剥离且正常正文保留；闭合边界转义；密钥在进窗与落库两道脱敏；正常业务纠偏及明确订单 ID 可用；派生结果保留最低信任与全部受限源，公开域和受限域分段；聚合 hit_count 正确。
- 验证方式与证据：实施提供攻防回归测试，验收检查真实 Run 请求与数据库事件；PEP 基准使用不超过 50 条候选，P95 ≤ 15 ms。

### TC-971-06：快照查看、敏感哨兵与审计失败

- 关联需求：AC-971-04、AC-971-05，BR-03、NFR-03 与设计评审 P1-1。
- 前提与数据：含合成敏感哨兵的已完成 Run 和加密快照。
- 操作步骤：通过页面鉴权查看快照；核对读取前后审计；查密文字段及其他投影字段；在隔离环境使快照查看审计写入失败，再次读取，恢复后重试。
- 预期结果：获授权用户看到脱敏结构与血缘/版本；敏感原值在库中投影、快照解密结果、审计与 HTTP 错误中均为零；审计失败返回 503 且无快照载荷；恢复后可查看并记录一次成功审计。
- 验证方式与证据：页面操作 + PG 直接核对 + 隔离故障注入；保存状态码和记录增量，不在报告展开原始哨兵。
- 清理：恢复隔离环境审计写入能力。

### TC-971-07：来源撤权、服务暂不可用与过期快照

- 关联需求：AC-971-05、AC-971-07，BR-03 与设计评审 P1-3。
- 前提与数据：同一快照包含两个独立受限来源；已创建引用它的 Badcase，另有未引用快照。
- 操作步骤：撤销任一来源的行/列或连接权限；重读快照、Badcase 与回放；恢复权限；暂时使来源授权核验不可用；将专属测试快照设为已过期并运行 Scheduler 清理入口。
- 预期结果：任一必要来源撤权均阻断解密/回放；不可用单独返回 503；轨迹与统计元数据查询不访问外部业务库；失效快照/Badcase给出 `snapshot_expired_or_revoked`；清理只删除已过期且未被 Badcase 引用的快照；正常业务历史保留。
- 验证方式与证据：真实 PG 权限变化、HTTP 结果、Scheduler 行为与数据库保留集合。
- 清理：恢复本用例变更的测试权限与故障服务。

### TC-971-08：只读 MCP 协议与调用审计

- 关联需求：AC-971-06，FR-07、BR-06。
- 前提与数据：有效租户作用域令牌，以及不同租户和成员的数据。
- 操作步骤：通过 HTTP JSON-RPC 完成 initialize、tools/list；调用四个只读工具；请求未知工具、写方法、越权 run_id、伪造 actor 和非法参数；使用无效令牌重试。
- 预期结果：仅列出四个登记工具；合法结果与同作用域控制台一致且包含脱敏元数据；拒绝非法方法和越权请求；不提供快照解密工具或明文；每次工具调用有审计记录，非法请求不改变业务数据。
- 验证方式与证据：HTTP 协议测试及 PG 审计记录增量；保留状态码和脱敏结果摘要。

### TC-971-09：Badcase 创建与确定性局部回放

- 关联需求：AC-971-07，FR-08。
- 前提与数据：具有冻结候选与版本元数据的 Run，包含预算淘汰的关键口径项。
- 操作步骤：在节点详情创建 Badcase 并填写根因/说明；取消一次后重新创建；不覆盖参数连续回放两次；调整预算、口径保护、压缩阈值与 observation 数量再执行。
- 预期结果：取消不写入记录，创建后列表可读；标题/说明落库前脱敏；原参数复现相同候选选择、装配与漏斗；候选策略准确展示新增/丢弃项、口径保留、Token 差异和安全结果；冻结源与版本保持；回放耗时小于 3 秒，模型与外部工具调用计数不增加。
- 验证方式与证据：Playwright + Agent/PG 核对 + 上游调用计数；保存回放对照截图和两次基线摘要。

### TC-971-10：观测故障隔离与零正文导出

- 关联需求：AC-971-01，BR-01、BR-05、NFR-02。
- 前提与数据：可控 OTLP 收集器或原版 Langfuse，带模型/工具正文哨兵的 Run。
- 操作步骤：完成 Run 并收集导出 Span；检查 trace_id 与父子关系；在原版 Langfuse 中查询同一 Trace，并实际点击 ContextOps 的公开项目链接；关闭受控导出目标再完成新 Run；使普通投影写入失败或队列满，提交正常 Run 和安全拦截 Run。
- 预期结果：三种 Context Span 使用约定的 retriever/guardrail/chain 类型，并关联既有 request/logical 链路；所有导出属性与事件中正文哨兵为零；导出/投影失败不阻断 Run，队列有界并增加诊断计数；安全事件落库失败有无正文的结构化安全日志；未启用 Langfuse 时控制台可用并说明入口状态。
- 验证方式与证据：内存导出器开发测试、实际 OTLP HTTP 捕获、原版 Langfuse API 与浏览器 Trace 页面、故障环境 Run 终态与安全日志；记录实际执行范围。

### TC-971-11：窄屏、键盘与请求恢复

- 关联需求：AC-971-02、AC-971-03、AC-971-07、UI-01。
- 前提与数据：1440 px 和 390 px 浏览器；正常、有错误和无记录的筛选状态。
- 操作步骤：用键盘切换标签、选择节点、打开快照、创建/取消 Badcase、编辑回放参数和关闭抽屉；在加载中切换 Run；对单个 UI 请求注入一次 503 后重试。
- 预期结果：列与控件对齐、全页无横向溢出，长 JSON 在组件内滚动；焦点可见，Esc 关闭并返回触发控件；加载和按钮等待状态明确；错误保留用户输入并可重试；切换 Run 不展示上一请求的迟到数据；顶部卡片在标签切换后仍保留。
- 验证方式与证据：浏览器实际页面、桌面/窄屏截图及键盘操作记录。网络替换只覆盖 UI 失败恢复，真实权限失败由 TC-971-04/06/07 覆盖。

### TC-971-12：迁移、SQL 与工程门禁

- 关联需求：AC-971-08、NFR-04。
- 前提与数据：`agent/main` 独立空库和带旧业务记录的 `0019` 库；遵循 [数据库验证矩阵](../../../docs/database-migrations.md#必须覆盖的验证)。
- 操作步骤：通过原生迁移及完整 SQL 分别初始化空库；通过原生迁移及增量 SQL 分别升级旧库；重跑目标版本、尝试错误起始版本；检查运行账号权限、恢复至 0019 后旧数据、重新升级及 SQL 再生成一致性；执行契约、综合检查和构建。
- 预期结果：四表与索引、版本记录符合设计；历史数据完整；运行账号无 DDL 能力，安全审计保持追加语义；错误起始版本拒绝；旧迁移不变；SQL 无漂移；规定门禁通过。
- 验证方式与证据：复用实施迁移集成测试和当前命令结果，验收记录实际执行/跳过范围；Web 无新增迁移。

### TC-971-13：四应用容器与实际模型链路

- 关联需求：AC-971-01、AC-971-02、AC-971-08，以及项目容器交付要求。
- 前提与数据：独立 Compose 项目、四应用镜像、两个 Agent 消费副本、独立 Scheduler、专属 PostgreSQL/Redis；原版 Langfuse 就绪，已配置真实 Flash Provider。
- 操作步骤：从容器 Web 登录并提交普通数据库分析问题，等待实际模型与授权 SQL 执行完成；从回答进入 ContextOps 并点击 Langfuse；核对三类 Context Span 和零正文；执行四应用 smoke；记录活跃 Run 的领取身份，向持租副本发送 SIGTERM 验证正常退出边界接管，再独立重启 Scheduler。
- 预期结果：普通问题按授权数据回答，Run、ContextOps 与 Langfuse Trace 对应；链接使用浏览器可达的公开项目地址；实际模型调用有完成状态与用量；Agent 接管后终态正确，Scheduler 重启恢复持租且不影响 Web/Agent 服务。
