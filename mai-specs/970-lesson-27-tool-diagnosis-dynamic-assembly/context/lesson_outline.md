## **第 27 课：内建工具体系诊断与场景化动态组装——治理工具粒度、边界与误选**

**本课目标：** 对 Compass 基线已实现的 19 个内建与业务工具进行系统性诊断与契约重构，并将静态全量平铺加载升级为“场景 × 执行阶段 × 角色”三维动态工具组装与按需发现机制，建立可量化的 Tool Eval 效果治理基线。

### **核心教学内容**

1. **企业内建工具池的典型劣化诊断：** 剖析随业务迭代自然堆积的工具体系病灶——职责边界交叉（如语义查询 `query_metric` 与底层 `database_query` 选择混乱）、操作链路过碎（一次语义确认拆成多次串行工具往返）、读写与管理类工具混入普通问答、参数自由度过高以及错误提示缺少自愈引导。
2. **面向大模型的工具设计准则（ACI）：** 从“面向前端/程序员的 API”转向“面向模型决策的 Tool Contract”，确立正交边界划分、枚举与强类型收敛、读写分离、可行动结构化报错（Actionable Error）以及大结果摘要分页准则。
3. **三层标准化 `ToolSpec` 契约：** 将工具声明解耦为模型可见语义层（功能边界、适用/禁用条件、参数说明与正反示例，衔接 PromptOps）、Runtime 执行约束层（超时、并发安全、幂等性、输出预算）与治理路由标签层（能力域、读写属性、风险等级、适用场景与阶段）。
4. **多工具加载退化机理与供给选型：** 分析工具数量从 5 个增长至 30+ 个时的准确率衰减与 Context Token 膨胀问题；比较全量静态注入、场景 Profile 绑定、阶段感知（Phase-aware）切换与两阶段按需发现（Deferred Tool Loading / `search_tools`）的适用边界。
5. **常驻核心集 + 场景动态集 + 按需发现集三层架构：** 保持高频底座工具（如完成提交、结果分页读取）常驻，按意图场景动态挂载主干业务工具，将低频长尾能力收敛至轻量索引并按需展开完整 Schema，突破单次调用 32 工具槽位上限。
6. **执行阶段可见面收敛：** 在规划（Plan）、取数（Query）、分析（Analyze）、核验（Verify）、交付（Deliver）各阶段动态收放工具可见面，防止探索阶段误触发资产变更或定稿工具。
7. **缓存友好性与持久恢复兼容：** 采用稳定排序保证同场景工具前缀命中 Prompt Prefix Cache；在跨进程恢复（Resume）时兼容历史步骤已调用的工具回执校验。
8. **Tool Eval 诊断指标与基准构建：** 建立工具选择准确率、参数合法率、首轮调用成功率、冗余调用率、错误自愈率与工具声明 Token 占比六维评测体系。

### **Compass 实战：19 个基线工具全景体检、正交重构与动态组装**

**业务场景：**

Compass 当前在 `catalog.py` 中集中登记了 19 个通用与业务工具（涵盖计划、SQL 查询、Python 分析、工作流、子 Agent、定时任务、语义发现/解析/查询/变更治理、文档检索等），默认采用扁平集合筛选。在混合问题压测下，普通查数会话同时暴露语义治理写工具与定时任务写工具，且模型在 `search_semantics`、`get_metric_definition`、`resolve_semantics`、`query_metric` 与 `database_query` 之间频繁出现多选、漏步与回退混乱。

**具体建设任务：**

- 构建 Compass 内建工具诊断评测集（覆盖边界混淆题、复杂参数题、缺参自愈题、只读/写操作混合题），跑出治理前基线报告。
- 对 19 个基线工具执行正交化体检与契约重构：厘清 `query_metric`（标准指标首选）与 `database_query`（探索性明细补充）的排他/降级边界，优化过碎的语义辅助链路与结构化自愈错误提示。
- 升级 `ToolSpec` 元数据，补充能力域、适用场景、执行阶段、读写与风险等级声明，并与 PromptOps 在线工具描述资产保持服务端 Schema 强校验同步。
- 改造 `catalog.py` 与 `loader.py`，联动第 21 课场景路由与 Context Profile，实现“常驻核心工具 + 场景/阶段动态挂载 + `search_tools` 长尾按需装载”。
- 在 Context/Tool Trace 中记录每轮候选工具池、装载规则命中原因、隐藏工具列表与工具声明 Token 开销。
- 基于同一诊断评测集完成“全量原始基线 vs 契约重构后全量装载 vs 契约重构 + 场景动态组装”三组对照实验。

### **验收标准**

| 验收维度 | 验收要求 |
| --- | --- |
| 边界正交性 | 19 个内建工具职责、优先顺序与降级关系清晰，消除同名异义与重叠描述 |
| 动态组装准确性 | 经营问答、深度分析、语义维护、定时任务等场景仅暴露最小充分工具集 |
| 容量扩展性 | 工具总池扩展至 40+ 时，单轮模型可见工具数量与声明 Token 保持受控 |
| 错误自愈能力 | 参数越界、口径缺失或字段不存在时，模型可根据结构化错误提示修正重试 |
| 恢复与缓存兼容 | 同场景前缀顺序稳定；持久 Run 中断恢复时不丢失已执行工具的核验能力 |
| 量化效果提升 | 评测集工具选择准确率与参数合法率显著提升，无效工具 Token 显著下降 |

**本课交付：** Compass 19 个内建工具体检报告、重构后的三层 `ToolSpec` 契约、场景与阶段动态 `Tool Assembler`、按需工具发现机制、Tool Eval 基准测试套件。
