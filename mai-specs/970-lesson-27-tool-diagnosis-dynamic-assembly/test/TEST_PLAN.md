## 范围与依据

验证用户通过普通 Chat 完成查数、深度分析、显式选择扩展、定时配置、指标治理和长任务的完整结果，同时覆盖三通道装载、极简参数适配、流式回答、引用与附件、暂停恢复和观测展示。业务预期取自 PRD；开发测试沿用项目入口，本计划重点补充跨模块结果与真实页面交互。

本课复用既有 PostgreSQL 表及 JSONB，无新增 DDL。仍需在真实 PostgreSQL 验证事务错误恢复、审批乐观锁、冻结工具快照、私有状态及跨进程恢复。数据库及凭据隔离遵守 [数据库规范](../../../docs/database-migrations.md)，所有测试数据使用合成数据。

本计划与实施计划的六批次对应：第 1 批固定原始声明和对照环境；第 2～4 批完成开发测试后开放对应业务用例；第 5 批检查页面和请求串联；第 6 批在最终版本重新核销全部 AC。必要条件未齐的用例保留待验。

## 待验业务用例

### TC-01：日常快查、口径解释和深度归因

- 关联需求：AC-01、AC-02、AC-04、AC-07。
- 前提与数据：同一维护者账号，语义、只读连接、资料、定时与 Sandbox 均可用；固定业务日期与已发布指标，包含可独立核算的总额/对照期数据。
- 操作步骤：分别提交不手选扩展的 SC-01 指标快查、SC-21 口径解释、SC-03 深度归因；在前两种场景中再提交轻度表述歧义和 SC-34 承接追问。
- 预期结果：快查和解释仅装载获准的 11 个常驻工具，深度归因增加计划/Python/子任务；口径解释按需要回答，预注入查询引用可直接使用；SC-34 补挂 Python。各回答与固定数据一致，声明体积和实际调用路径可从轨迹核对。
- 验证方式与记录：真实 Chat + ContextOps/模型请求轨迹；保存问题、路由场景、实际工具名称/字节、查询引用及回答。组装前缀相同只记录序列哈希，Provider 缓存用量另按实际返回记录。

### TC-02：手动选择、移除、空态与跨会话隔离

- 关联需求：AC-04、AC-05、AC-06、AC-10。
- 前提与数据：本人至少两条已启用工作流、一条多工具 MCP 连接；另有其他用户私有连接。准备无扩展账号。
- 操作步骤：在工具与扩展浮层选择工作流编排、一个个人工作流和 Python；移除一个徽标后发送。重新进入会话并查看请求；切换账号/工作区，验证可选项更新。无扩展账号打开浮层。
- 预期结果：按钮计数和徽标一致；`constraints.toolSelection` 只带实际选择；本轮挂载对应授权工具；未选资产保持未挂载。空态显示“暂无已启用的个人工作流 / 外部连接”，其他用户资产不出现在选择项或轨迹中。
- 验证方式与记录：浏览器及提交请求、真实 Run 工具列表；UI fixture 用于错误/空态，真实服务验证最终挂载。

### TC-03：扩展上限、慢 MCP 与授权池容量

- 关联需求：AC-05、AC-06、AC-11，FR-11。
- 前提与数据：隔离用户持有 10 条工作流和若干合计 20 个工具的 MCP 连接，至少一条连接可模拟超时；全部静态能力可用。
- 操作步骤：先不勾选 MCP 提交快查；再选择可用连接，分别达到 12 个扩展工具、尝试超出 12；另用已经发现的 49 工具 fixture 验证冻结池及恢复。
- 预期结果：普通未选 MCP 的运行无需访问该远端，慢连接不拖延普通查数；勾选按连接下实际工具数累计，达到上限后禁用未选项并显示 COPY-06；服务端保持 12 项扩展与单步 32/64 KiB 上限。已发现的 49 工具可入授权池并冻结，未挂载项进入延迟池；组装实测小于 2 ms。
- 验证方式与记录：远端调用计数、UI 请求、授权池快照、容量测试及计时。性能记录样本数、运行环境和计算方式。
- 清理：删除本用例创建的测试工作流/MCP，保留既有用户资产。

### TC-04：权限与运行身份边界

- 关联需求：AC-06、AC-08、AC-10。
- 前提与数据：普通分析成员、语义维护者、跨租户账号，独立 Scheduler/子任务运行。
- 操作步骤：普通成员构造包含 `semantic_govern` 和他人 MCP ID 的提交请求；构造未暴露工具调用；主任务派发只读子任务；触发一次测试定时运行。
- 预期结果：前端普通成员隐藏治理组，服务端过滤无权项且直接调用被拒；工具名、连接详情和错误候选均不泄露。子任务仅继承父级可见只读非审批非编排能力及专用底座，定时运行始终排除 `schedule_write`。
- 验证方式与记录：真实权限 API/运行轨迹与拒绝回执，辅以既有身份隔离集成测试；ContextOps 仅显示权限过滤计数。

### TC-05：单参数 SQL、多连接元数据与错列自愈

- 关联需求：AC-02、AC-03、AC-09。
- 前提与数据：两套具有不同获准 schema 的只读连接、一个同名 schema 冲突组合、包含无权表列的受限角色。独立 SQL 核对固定数据预期。
- 操作步骤：先查获准 `information_schema.tables/columns`，再查业务明细；故意传错一个列名，按返回候选修正；访问无权表/列；最后导出 CSV。补查同名 schema 情形。
- 预期结果：仅传 `sql` 即可聚合获准元数据并确定路由；错列后同事务可继续查询，回执给出字段与至多 8 个获准列候选；无权资源使用脱敏拒绝。纯元数据来源可持续核验，随后导出成功；结果双句柄同值且可供后续工具读取。连接歧义清楚反馈，执行所选连接与用户数据范围一致。
- 验证方式与记录：真实 PostgreSQL、模型修复调用链、来源类型、CSV 内容和权限负例；不使用 SQLite 替代保存点与角色验证。

### TC-06：渐进读取、历史资料和 Python 超限恢复

- 关联需求：AC-02、AC-03，FR-08。
- 前提与数据：超过 128 KiB 的合成查询结果、可聚合的小结果、带两代生效日期的资料。
- 操作步骤：分页读取大结果，续页同时传 cursor 与 offset；将大结果送入 Python，根据提示聚合后重试并下载图表；按历史业务日搜索并打开资料相邻段。
- 预期结果：cursor 决定续页；Python 超限返回 COPY-08 所需大小与修复动作，聚合后完成并保留查询血缘；指定业务日命中对应历史有效版本，未指定时检索当前版本。完整结果、引用和图表保持授权边界。
- 验证方式与记录：真实 SQL/Python、分页内容、授权来源和下载文件；参数/超限自动化与界面观察合并记录。

### TC-07：计划、长任务与子任务无损适配

- 关联需求：AC-03、AC-06、AC-08、AC-09，FR-09。
- 前提与数据：包含两个可核验子目标的长任务，有明确成功标准和有限预算；准备一个部分失败子任务及一个无权输入引用。
- 操作步骤：手动选择长任务和个人工作流后提出目标、确认；更新完整 todos 列表并重放同一请求；派发两个子任务，交回结论/缺口；记录对应 `acceptanceIndexes`；让控制循环启动下一轮，再验证完成与阻塞分支。
- 预期结果：Todo 进度环和已有状态机保持一致；重复调用幂等；子任务证据仅进入授权账本且单次交付；缺口/blocked 状态保留；完成需要现行门禁满足；自动下一轮继承工具选择，暂停、取消与用户插话沿用既有行为。
- 验证方式与记录：真实 PostgreSQL Goal/父子运行、页面面板和选择快照；引用既有长任务集成与浏览器用例，补足本课参数和选择继承断言。
- 清理：结束本用例新建目标，保留其审计与历史记录。

### TC-08：工作流试跑、确认保存与旧脚本复用

- 关联需求：AC-03、AC-08、AC-09。
- 前提与数据：具备工作流权限；一条已保存旧 `{prompt}` 子任务脚本，新脚本使用 `{tasks}`。
- 操作步骤：显式勾选工作流编排并提交沉淀请求；完成试跑、确认保存，换周期复用；分别执行新旧脚本；试跑一次参数不匹配后按字段提示修复；不勾选但明确命中 SC-29/30 再提交。
- 预期结果：新旧脚本可调用既有执行入口，错误可定位修复，保存仍需原确认；显式编排场景自动补齐获准编排能力，常规查数不装载未选工作流。
- 验证方式与记录：真实试跑结果、保存邀请、资产列表与复用轨迹，复用 hybrid-workflow 回归。
- 清理：删除新建测试资产；保留作为兼容夹具的旧脚本。

### TC-09：定时读写与并发审批版本

- 关联需求：AC-06、AC-08、AC-09。
- 前提与数据：计划所有者、已选主模型、明确工作区时区；两浏览器会话用于同一测试计划。
- 操作步骤：创建 daily/weekly 简写与五段 Cron 计划；读取列表和详情；修改/暂停并在确认卡生成后从另一会话更新同一计划，再确认旧卡；最后取消或删除测试计划。
- 预期结果：读取包含所需问题与执行历史；服务端填入时区/模型和版本；写入前显示审批摘要，取消无写入；过期版本确认被拒且可按最新状态重试；重复确认仅生效一次，历史执行保留。
- 验证方式与记录：确认卡、计划版本、触发时间、真实 PostgreSQL 审批恢复测试；各运行选用正确身份。
- 清理：停用并删除新建测试计划，避免后续自动触发。
