## 实现校准

- 沿用设计的中断语义、连接修订号和默认预算。自动轮停止后才提交插话；用户主动暂停持续生效。排队后尚未执行的取消轮不消耗轮数，下一次准入使用新请求标识。
- 自动续轮等待 Run 的终态与 outbox 投递。结算只汇总已接受的调用，覆盖子任务；跨实例重复扫描、重放及重试保持幂等。
- 每步将目标锚点装配到系统前缀并计入固定输入预算，历史选择 / 压缩保留当前契约、未完成项和失败项。相同待办与失败跨 Run 重写不制造进展。
- 跨 Run 复用导入完整证据依赖闭包，重映射引用 ID，并复核当前来源授权。大查询复用原件 manifest，分页读取继续核权；工具成功事件的 `rowCount` 接受完整结果行数，预览边界保持原约束。
- 连接修订变化时查询与结论进入待补查；已完成写入保留产物、摘要和原数据版本，内层证据与外层回执使用同一当前授权修订。受控执行适配器实际写入 PNG，重复恢复保持一次写入及相同 SHA-256。
- 委派工具和连接范围取父执行域与请求的交集，输入引用经当前授权核验后才导入子执行域。首次委派保存稳定快照；重放复核授权并沿用快照。`final` 回传立即停止对应子任务，账本仅合入一次。
- `goal` 的持久状态回执和子任务结果声明明确来源依赖，避免大回执被错误标记为当前执行期临时数据。真实模型产生的简单多分支 `UNION` 查询逐叶建立授权来源，任一不可认证叶仍保持原有临时来源规则。
- 取消时从已投递视图及未投递 outbox 合并最新执行节点版本，再生成终态，避免进度刚落库时覆盖同版本记录。
- 子树接口放在独立 `api/goals.py`，复用既有历史、来源和可见性投影；主 SSE 契约保持完整。前端轮询目标与授权子树，权限收紧时清除已加载详情。

## 首页 Showcase 补充（2026-11-24）

用户确认保留「经营变化归因」「从经营诊断到行动方案」两个案例。前者对比 2025 年 11 月与 10 月，汇总渠道、商品及相关因素的变化并生成贡献图；后者经目标确认后完成问题排序、归因调查和两周经营方案。两份预填原文保持用户确认版本，通过既有首页候选问题与 PromptOps 发布机制接入。

实现源为 Agent `promptops/analysis_showcases.json` 及 `prompts/support/starters/analysis/operating-attribution.md`、`operating-action-plan.md`。首页沿用点击预填、返回输入框、用户发送的交互，不增加专属执行分支。真实模型首页验收结果另记 `test/SHOWCASE_REPORT.md`；本补充在该验收完成前保持待验。

本次首页配置补充的 Agent lint、typecheck、常规测试（578 通过、8 跳过）及 wheel 构建均通过；两个新增问题及目录配置格式检查通过。PromptOps 已分别发布为 generation 71、72，保留其余在线版本。真实模型验收正在执行，最终业务结果以本次 Showcase 报告为准。

真实首页验收补齐两处集成修复：

- 大结果的来源复核：原实现比较 5 行原文件预览与 50 行普通查询预览，导致合法结果被拒绝。JSONL 结果现在登记完整文件摘要、行数、列与完整性；复核经相同只读 SQL 校验和当前受限连接流式计算全量摘要。原有 inline 指纹保持兼容。255 行真实 PostgreSQL 查询与原文件摘要一致，末行改变的回归用例拒绝复用。
- 执行过程预览：完整内联结果上限高于 SSE 预览上限，大商品列表触发事件 DTO 校验错误。超过 SSE 限额时使用已有展示摘要截断，完整模型和沙箱输入保持；192 行中文商品结果到图表产物的测试通过。工具异常诊断只记录工具名、异常类型和函数行号。

以上修复后从首页重新执行两条原文 Prompt，最终验收待本次报告记录。

进一步修复 Sandbox 创建前拒绝的持久状态：输入引用无效、来源失效、输入超限或绑定不适用时，返回 `rejected / not_started` 回执，让物理调用账本保存确定结果；此前异常逃出已登记的物理调用会形成 `unknown` 并阻断恢复。新增用例确认无输入源时不会进入资源分配，相关 Sandbox/工具运行 14 项测试通过。后续真实模型继续使用已确认原文。

- 首页真实模型续测修复：默认术语与此前授权输入会一起保存在查询证据中，原账本单条 16 来源上限使正常结论返回 `ledger_source_limit`。账本与查询复用统一改为最多 256 来源、来源 JSON 最多 512 KB，保留全部来源及权限复核。新增 PostgreSQL 回归验证 48 来源原样持久化、数量和字节超限均拒绝且不留下条目；本次 PostgreSQL 目标运行集成全套 22 项通过（含来源保留、授权和恢复边界）。设计 §2 同步容量约束。真实模型最终交付仍在验收中。

- 暂停续轮状态修复：真实页面暂停后，目标锚点以 `goal_inactive` 停止已领取续轮，通用预算异常映射成 `internal_error`。现在用户暂停的目标使用明确 `goal_paused` 停止原因，并由 RunControl 提交正常的用户取消、清理确认结果。12 项运行自治测试和 23 项 PostgreSQL 目标集成测试通过。当前真实模型在途轮次先保持运行，修复待自然边界后加载。

- 长任务来源检查优化：账本条目保存的授权来源大量重叠，逐条实时核验会反复重放同一查询。`Ledger.visible` 和恢复校验在每次操作内先合并去重来源并实时核验；全部可读时复用本次检查结果，存在拒绝时仍逐条判定并传播依赖不可见状态。没有跨请求授权缓存。回归覆盖共享来源只检查一次、局部拒绝与依赖过滤；原授权撤回和恢复集成仍保留。
- 通用提示词补充：独立调查在范围和连接明确后优先委派；跨轮计算前通过同参数查询复用登记本轮输入。首页两个已确认问题原文保持不变。PromptOps 仅发布这两个共享片段至 generation 73/74，其他在线版本保持原样。

- 大历史续跑修复：真实续跑的内部摘要输入约 14 万字节，2048-token 输出被截断，回退原历史后触发 `context_limit`。压缩改为同时受输入和输出预算约束的分批交接，短摘要保留回读位置；截断只用原材料缩小批次有限重试，不接受截断文本或标记其已覆盖。保持模型及总预算上限、失败回退规则。当前 v2 路径每批摘要独立受 25 秒与 Run 剩余时间约束，没有整段共用 25 秒父阶段限制。
- 已完成查询的取消边界修复：数据库读取关闭连接后返回的值明确标记 `settled_on_return`，在持久回执发布阶段取消时保留已完成记录并确认清理；操作尚未返回仍保持未知状态。结果来源登记与连接授权本地读取通过受跟踪任务等待结束后确认取消，避免线程登记尚在收尾即永久标为清理未确认。真实 PostgreSQL 回归验证返回前/返回后取消差异，另验证来源登记取消会等事务结束。
